## 17:10 诊断「命名空间中不存在 MainWindow」报错（连锁症状）
- 现象：MainWindow.xaml:18 `<Style TargetType="{x:Type local:MainWindow}">` 报「clr-namespace:DoubleSmileChat 中不存在 MainWindow 名称」
- 诊断：x:Class / xmlns:local / 类名 / csproj 全部正确；时间戳显示 obj\Debug 的 g.cs+baml+exe 停在 9-27 17:40，而源文件已改到 9-29 16:52 → 从 9-27 之后从未编译成功，报错只是连锁症状
- 真错误 1：BasePage 已被用户改成泛型 `BasePage<VM>`（项目里已无同名非泛型类），LoginPage.xaml 根元素仍写 `<local:BasePage>` → 类型不存在。修：根元素加 `x:TypeArguments="vm:LoginViewModel"` + `xmlns:vm="clr-namespace:DoubleSmileChat.ViewModel"`
- 真错误 2：ViewModel/WindowViewModel.cs 调用 `SystemCommands.ShowSystemMenu` 但缺 `using System.Windows.Shell;` → CS0103。修：补 using
- 顺手修：Pages/BasePage.cs 注释里过时的 `<see cref="SlideAnimations"/>` 改成 PageAnimations
- 已同步技能 wpf-xaml-pitfalls：新增 3.1 节（泛型基类根元素必须用 x:TypeArguments）、第 6 节补「设计器报类型不存在的第一诊断招 = 比对 obj 产物与源文件时间戳」+ 高频 CS0103（SystemCommands 缺 using）
- 环境备忘：MSBuild、Shell 宿主进程均被安全策略判为 LOLBin 拦截，无法本地编译；只能用「静态审查 + 时间戳法」定位
- 待办观察：LoginPage 按钮已从 Click 事件改为 `Command="{Binding LoginCommand}"`，目前无任何地方调用 AnimateOut；且 BasePage 泛型化后，日后做页面切换需要统一调用 AnimateOut 时会缺一个非泛型入口（建议加接口或保留非泛型基类）
